## Как пользоваться этим файлом

**1. Сначала сделай «точку отката».** Открой терминал в папке проекта и выполни:

```
git add -A
git commit -m "До исправлений"
git checkout -b fixes
```

Теперь все правки идут в отдельную ветку `fixes`. Если что-то сломается, вернуться можно командой `git checkout main`.

**2. Четыре вида правок:**

- **«Найди → Замени на»**. Открой файл в VS Code, нажми `Ctrl+F`, вставь в поиск **первую строку** из блока «Найди». Выдели весь найденный кусок и вставь вместо него блок «Замени на». Примерный номер строки указан рядом (`Ctrl+G` — переход к строке).
- **«Замени весь файл»**. Открой файл, `Ctrl+A`, `Delete`, вставь новый текст целиком. Так сделано там, где правок слишком много, а старый код почти весь состоял из встроенных стилей.
- **«Создай новый файл»**. Создай файл с указанным именем в указанной папке.
- **«Вставь в самый конец»**. Только один раз, в `styles.css` (этап 8.9).

Над каждой правкой написано, в каком она файле: 📄 **Файл:** `...`. Если в блоке «Найди» у тебя отличаются только пустые строки или пробелы в конце строк — это нормально, заменяй.

**3. После каждого этапа проверяй.** В конце этапа есть блок «Проверка». Если результат не совпал, остановись и пришли мне, что видишь: текст ошибки из терминала или из консоли браузера (`F12` → вкладка Console).

**4. Порядок важен.** Делай этапы по порядку: сначала бэкенд, потом общие файлы фронтенда, потом страницы и в конце стили. Страницы используют функции из `api.js` (этап 2), поэтому без него они не заработают.

**Как перезапускать сервер.** В терминале в папке `backend`: `Ctrl+C`, затем `node server.js`. Страницы (HTML/CSS/JS) перезапуска не требуют, достаточно обновить страницу в браузере через `Ctrl+F5` (обновление без кэша).

# ЭТАП 1. Бэкенд (папка `backend`)

С него начинаем, потому что без работающей базы фронтенду нечего показывать.

## 1.1 `backend/db.js`: подключение к базе

**Что делает файл.** Создаёт пул соединений с PostgreSQL, при запуске создаёт таблицы, если их нет, и содержит функцию `pgToSqlite`. Она на лету переделывает старые SQL-запросы в стиле SQLite (`?`) в стиль PostgreSQL (`$1, $2`).

**Правка 1: путь к `.env`, числа вместо строк, никаких «угаданных» паролей.**

Что было не так:
- `require('dotenv').config()` без пути ищет `.env` в папке, **откуда запущен** `node`. Если запустить `node backend/server.js` из корня проекта, файл `backend/.env` не находится.
- `password: process.env.PGPASSWORD || 'postgres'`: если пароль не прочитался, код молча подставлял слово `postgres`. Отсюда твоя ошибка «пароль не прошёл проверку».
- PostgreSQL отдаёт `BIGINT` (поле `created_at`, результат `COUNT(*)`) **строкой**, и `new Date("1790...")` даёт «Invalid Date».

📄 **Файл:** `backend/db.js`

**Найди** (≈ строка 3):
```js
const { Pool } = require('pg');
require('dotenv').config();

// Подключение к PostgreSQL
const pool = new Pool({
  host: process.env.PGHOST || 'localhost',
  port: process.env.PGPORT || 5432,
  database: process.env.PGDATABASE || 'buildstorenet',
  user: process.env.PGUSER || 'postgres',
  password: process.env.PGPASSWORD || 'postgres',
```
**Замени на:**
```js
const path = require('path');
const { Pool, types } = require('pg');
// .env ищем рядом с этим файлом (в папке backend), а не там, откуда запущен node
require('dotenv').config({ path: path.join(__dirname, '.env') });

// BIGINT (created_at, COUNT(*)) pg по умолчанию отдаёт строкой — превращаем в число,
// иначе new Date("1790...") на фронтенде даёт «Invalid Date»
types.setTypeParser(20, (value) => (value === null ? null : Number(value)));

// Без пароля в .env не стартуем — лучше понятная ошибка, чем «угадывание» пароля
if (!process.env.PGPASSWORD) {
  console.error('❌ В backend/.env не задан PGPASSWORD — сервер не сможет подключиться к базе');
}

// Подключение к PostgreSQL
const pool = new Pool({
  host: process.env.PGHOST || 'localhost',
  port: process.env.PGPORT || 5432,
  database: process.env.PGDATABASE || 'buildstorenet',
  user: process.env.PGUSER || 'postgres',
  password: process.env.PGPASSWORD,
```

> **Что такое `types.setTypeParser(20, ...)`.** У каждого типа данных в PostgreSQL есть номер, у `BIGINT` это 20. Эта строка говорит библиотеке `pg`: «значения этого типа превращай в обычное число». Даты в миллисекундах помещаются в число JavaScript без потерь.

**Правка 2: сохраняем «обещание» готовности базы.**

Раньше `initDatabase().catch(console.error)` запускалась «в фоне». Сервер открывал порт, не дожидаясь базы, и писал «✅ Сервер запущен», даже когда пароль был неверный.

📄 **Файл:** `backend/db.js`

**Найди** (≈ строка 151):
```js
// Запускаем инициализацию
initDatabase().catch(console.error);
```
**Замени на:**
```js
// Запускаем инициализацию. Сохраняем «обещание», чтобы server.js
// мог дождаться готовности базы ПЕРЕД тем, как принимать запросы
const dbReady = initDatabase();
```

> **Что такое Promise («обещание»).** `initDatabase()` — асинхронная функция: она возвращает объект, который «пообещал» закончиться позже, успехом или ошибкой. Мы сохраняем его в `dbReady`, а в `server.js` скажем: «когда `dbReady` выполнится, запускай сервер».

**Правка 3: поиск без учёта регистра.**

В PostgreSQL `ILIKE` ищет без учёта регистра, а `LIKE` с учётом. Функция `pgToSqlite` зачем-то меняла `ILIKE` на `LIKE`, и поиск «кирпич» не находил «Кирпич». Я проверил это на живой базе.

📄 **Файл:** `backend/db.js`

**Найди** (≈ строка 196):
```js
  return out
    .replace(/\bILIKE\b/gi, 'LIKE')
    .replace(/CAST\(([^()]*)AS\s+REAL\)/gi, 'CAST($1 AS DOUBLE PRECISION)');
```
**Замени на:**
```js
  // ILIKE НЕ трогаем: в PostgreSQL это и есть поиск без учёта регистра
  // (раньше он заменялся на LIKE, и «кирпич» не находил «Кирпич»)
  return out
    .replace(/CAST\(([^()]*)AS\s+REAL\)/gi, 'CAST($1 AS DOUBLE PRECISION)');
```

📄 **Файл:** `backend/db.js`

**Найди** (≈ строка 202):
```js
module.exports = {
  pool,
  pgToSqlite,
```
**Замени на:**
```js

  pool,

  pgToSqlite,
```

**Правка 3: разрешаем браузеру читать заголовок `X-Total-Count`.**

Сервер сообщает общее количество товаров в заголовке ответа `X-Total-Count`, но браузер по умолчанию прячет от JavaScript почти все заголовки. Список `exposedHeaders` говорит: «этот можно показывать». Без него пагинация перестанет работать, как только фронтенд и бэкенд окажутся на разных адресах, например на твоём сервере.

📄 **Файл:** `backend/server.js`

**Найди** (≈ строка 54):
```js
app.use(cors(allowedOrigin ? { origin: allowedOrigin } : {}));
```
**Замени на:**
```js
// exposedHeaders — чтобы фронтенд мог прочитать общее число товаров из заголовка X-Total-Count
app.use(cors(allowedOrigin
  ? { origin: allowedOrigin, exposedHeaders: ['X-Total-Count'] }
  : { exposedHeaders: ['X-Total-Count'] }));
```

**Правка 4: без секрета на боевом сервере не запускаемся.**

В `routes/auth.js` есть запасной секрет `'dev-secret-key'`, и его видно всем в открытом репозитории на GitHub. Если на сервере забыть `JWT_SECRET`, любой сможет подделать токен, в том числе токен админа. Локально останется только предупреждение, а на сервере (`NODE_ENV=production`) запуск будет остановлен.

📄 **Файл:** `backend/server.js`

**Найди** (≈ строка 59):
```js
// Предупреждение о секретах (не падаем, чтобы не ломать локальную разработку)
if (!process.env.JWT_SECRET) {
  console.warn('⚠️  JWT_SECRET не задан — используется fallback из routes/auth.js. Для продакшена задайте JWT_SECRET в .env!');
}
```
**Замени на:**
```js
// Секрет для подписи токенов. Локально — только предупреждение,
// на боевом сервере (NODE_ENV=production) без него не запускаемся:
// запасной секрет виден всем в открытом репозитории на GitHub
if (!process.env.JWT_SECRET || process.env.JWT_SECRET.length < 32) {
  if (process.env.NODE_ENV === 'production') {
    console.error('❌ JWT_SECRET не задан или короче 32 символов. Задайте его в backend/.env');
    process.exit(1);
  }
  console.warn('⚠️  JWT_SECRET не задан или короче 32 символов — для продакшена задайте его в .env!');
}
```

**Правка 7: корректная остановка (переменная `server` теперь может ещё не существовать).**

📄 **Файл:** `backend/server.js`

**Найди** (≈ строка 221):

  if (server) server.close(() => process.exit(0));
  else process.exit(0);
}

process.on('SIGTERM', () => shutdown('SIGTERM'));

> **Про «кракозябры» в ошибках на Windows.** Сообщения вида `������������ "postgres"` — это не отдельный баг. PostgreSQL на русской Windows пишет ошибки в кодировке cp1251, а консоль Node читает их как UTF-8. Смысл остаётся тем же, в твоём случае это была «password authentication failed» (неверный пароль).

### Проверка после 1.1–1.2

1. `Ctrl+C`, затем `node server.js`. При **правильном** пароле внизу должно быть `✅ Сервер запущен: http://127.0.0.1:4000`, после строк `✅ Table ... initialized`.
2. Открой в браузере `http://127.0.0.1:4000/api/health`. Должно быть `{"ok":true,"db":"connected"}`.
3. Для интереса временно испорти `PGPASSWORD` в `.env` и запусти ещё раз. Должна появиться одна понятная строка «❌ Не удалось подключиться к PostgreSQL...», и сервер остановится. Верни пароль обратно.

## 1.3 `backend/routes/listings.js`: объявления

**Что делает файл.** Обрабатывает `/api/listings`: список с фильтрами, одно объявление, создание, изменение и удаление. Для организаций здесь же проверяется, обязателен ли сертификат.

**Правка 1: единый список категорий и проверка цены.**

Добавляем три вещи:
- `CATEGORIES` — единственный правильный список категорий. Сервер отклонит объявление с «Крепеж» без «ё», а ведь раньше это молча создавало вторую «категорию-близнеца».
- `parsePrice()` — пропускает только числа. Раньше `'договорная'` проходила проверку, потому что `NaN < 0` в JavaScript равно `false`.

function parsePrice(value) {
  const text = String(value == null ? '' : value).trim().replace(',', '.');
  if (!/^\d+(\.\d{1,2})?$/.test(text)) return null;
  const num = Number(text);
  return Number.isFinite(num) && num >= 0 && num <= 1e9 ? String(num) : null;

## 1.7 Почистить старые данные в базе

Новые правила не пустят в базу плохие данные, но старые записи там уже могут лежать. Открой pgAdmin → своя база → **Query Tool** и выполни по очереди.

**Посмотреть, какие категории есть в базе:**
```sql

```

**Если видишь «Крепеж» без «ё», исправь:**
```sql
UPDATE listings SET category = 'Крепёж' WHERE category = 'Крепеж';
```

**Найти объявления с ценой-текстом:**
```sql
SELECT id, title, price FROM listings WHERE price !~ '^[0-9]+(\.[0-9]+)?$';
```
Их можно поправить вручную, например `UPDATE listings SET price = '1500' WHERE id = 7;`, или удалить. Если оставить, сайт не сломается: в карточке будет «Цена не указана», а заказать такой товар будет нельзя, с понятным сообщением.

    const m10 = n % 10, m100 = n % 100;
    if (m10 === 1 && m100 !== 11) return one;

## 5.2 `frontend/js/add.js` — замени весь файл

Что изменилось:
- **Главный баг: сертификат не отправлялся.** Старый код читал файл, но не клал его в запрос. Теперь файл превращается в строку base64 (`FileReader.readAsDataURL`) и уходит в поле `certificateBase64`. Сервер его проверяет и сохраняет в `uploads/certificates`.
- Перед показом формы страница спрашивает `/api/auth/me`. Если ты организация со статусом «на проверке» или «отклонена», сверху сразу выводится объяснение, а кнопка «Опубликовать» блокируется. Раньше человек заполнял всё и только потом получал отказ.
- Размер файлов проверяется до отправки: фото до 5 МБ, сертификат до 10 МБ, как на сервере.
- Цена проверяется как на сервере: только число, до двух знаков после точки. Запятую `1500,50` страница сама меняет на точку.
- После успеха — переход на страницу нового товара.

📄 **Файл:** `frontend/js/add.js` — **замени всё содержимое** (`Ctrl+A`, `Delete`, вставить):

// ============================================================
// ДОБАВЛЕНИЕ ОБЪЯВЛЕНИЯ (add.js) — для add.html
// ============================================================
// Что изменилось по сравнению со старой версией:
// 1. Сертификат (поле #certificate) теперь реально отправляется на сервер
//    в поле certificateBase64 — раньше он читался формой, но терялся.
// 2. Звёздочка «обязателен» у сертификата появляется для организаций
//    в категориях «Электроинструмент» и «СИЗ».
// 3. Если организация ещё на проверке — сразу показываем это, а не ошибку после отправки.
// 4. Ошибки показываются текстом под формой, а не alert с фигурными скобками.
(function () {
  'use strict';

  const api = window.BuildStoreApi;
  const form = document.getElementById('addForm');
  if (!form) return;

  // Должно совпадать с CERT_REQUIRED_CATEGORIES в backend/routes/listings.js
  const CERT_REQUIRED_CATEGORIES = ['Электроинструмент', 'СИЗ'];
  const MAX_IMAGE = 5 * 1024 * 1024;   // 5 МБ — как на сервере
  const MAX_CERT = 10 * 1024 * 1024;   // 10 МБ — как на сервере

  const errorBox = document.getElementById('addError');
  const submitBtn = document.getElementById('submitBtn');
  let isOrganization = false;

  function showError(text) {
    errorBox.textContent = text;
    errorBox.hidden = false;
    errorBox.scrollIntoView({ behavior: 'smooth', block: 'center' });
  }

  function readAsDataURL(file) {
    return new Promise((resolve, reject) => {
      const reader = new FileReader();
      reader.onload = () => resolve(reader.result);
      reader.onerror = () => reject(new Error('Не удалось прочитать файл ' + file.name));
      reader.readAsDataURL(file);
    });
  }

  function updateCertMark() {
    const category = document.getElementById('category').value;
    document.getElementById('certRequiredMark').hidden =
      !(isOrganization && CERT_REQUIRED_CATEGORIES.includes(category));
  }
  document.getElementById('category').addEventListener('change', updateCertMark);

  // Узнаём, кто размещает: частное лицо или организация, и её статус
  async function checkSeller() {
    if (!api.getToken()) {
      window.location.href = '/frontend/auth.html';
      return;
    }
    try {
      const res = await api.apiFetch('/auth/me', { headers: api.authHeaders() });
      const me = await res.json();
      isOrganization = me.type === 'organization';
      const notice = document.getElementById('sellerNotice');
      if (me.status === 'pending' || me.status === 'rejected' || me.status === 'blocked') {
        notice.textContent = me.status === 'pending'
          ? 'Ваша организация проходит проверку. Размещение объявлений станет доступно после подтверждения документов модератором.'
          : me.status === 'rejected'
            ? 'Заявка организации отклонена' + (me.reject_reason ? ': ' + me.reject_reason : '') + '. Размещение объявлений недоступно.'
            : 'Аккаунт заблокирован, размещение объявлений недоступно.';
        notice.hidden = false;
        submitBtn.disabled = true;
      }
      updateCertMark();
    } catch (err) {
      if (err.status === 401) window.location.href = '/frontend/auth.html';
    }
  }

  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    errorBox.hidden = true;

    const title = document.getElementById('title').value.trim();
    const category = document.getElementById('category').value;
    const price = document.getElementById('price').value.trim();
    const description = document.getElementById('description').value.trim();
    const photo = document.getElementById('photo').files[0];
    const certificate = document.getElementById('certificate').files[0];

    // Та же проверка, что на сервере — чтобы не отправлять заведомо неверную форму
    if (title.length < 2) return showError('Укажите заголовок (минимум 2 символа)');
    if (!category) return showError('Выберите категорию');
    if (!/^\d+([.,]\d{1,2})?$/.test(price)) return showError('Укажите цену числом, например 1500');
    if (photo && photo.size > MAX_IMAGE) return showError('Фото больше 5 МБ');
    if (certificate && certificate.size > MAX_CERT) return showError('Сертификат больше 10 МБ');
    if (isOrganization && CERT_REQUIRED_CATEGORIES.includes(category) && !certificate) {
      return showError(`Для организаций в категории «${category}» сертификат или паспорт товара обязателен`);
    }

    submitBtn.disabled = true;
    submitBtn.textContent = 'Публикуем…';
    try {
      const body = { title, category, price: price.replace(',', '.'), description };
      if (photo) body.imageBase64 = await readAsDataURL(photo);
      if (certificate) body.certificateBase64 = await readAsDataURL(certificate); // ← этого раньше не было

      const res = await api.apiFetch('/listings', {
        method: 'POST',
        headers: api.authHeaders({ 'Content-Type': 'application/json' }),
        body: JSON.stringify(body)
      }, 20000); // файлы могут быть большими — ждём дольше обычного

      const created = await res.json();
      window.location.href = '/frontend/product.html?id=' + encodeURIComponent(created.id);
    } catch (err) {
      showError(err.message);
      submitBtn.disabled = false;
      submitBtn.textContent = 'Опубликовать';
    }
  });

  checkSeller();
})();
```

> **Что такое base64.** Способ записать любой файл (картинку, PDF) обычными буквами и цифрами, чтобы положить его в JSON. Строка начинается с `data:application/pdf;base64,...`, и сервер по этому началу понимает тип файла.

      container.innerHTML = emptyState(ICON_LOCK, 'Войдите, чтобы увидеть свои заказы', '/frontend/auth.html', 'Войти');
      return;
    }
    try {
      const res = await api.apiFetch('/orders', { headers: api.authHeaders() });
      const orders = await res.json();
      container.classList.remove('loading');

      if (!orders.length) {
        container.innerHTML = emptyState(ICON_BOX, 'У вас пока нет заказов', '/frontend/listings.html', 'Перейти в каталог');
        return;
      }
      container.innerHTML = orders.map(orderCardHtml).join('') +
        '<div style="text-align:center; margin-top:24px;"><a href="/frontend/listings.html" class="btn btn-secondary">Продолжить покупки</a></div>';
    } catch (err) {
      container.classList.remove('loading');
      if (err.status === 401) {
        container.innerHTML = emptyState(ICON_LOCK, 'Сеанс истёк, войдите заново', '/frontend/auth.html', 'Войти');
        return;
      }
      console.error('Ошибка загрузки заказов:', err);
      container.innerHTML = `<div class="empty-state"><div class="empty-state-title">Не удалось загрузить заказы</div><div class="empty-state-description">${esc(err.message)}</div></div>`;
    }
  }

  // ---------- Окно с деталями заказа ----------
  async function showDetails(orderId) {
    const dialog = document.getElementById('orderDialog');
    const body = document.getElementById('orderDialogBody');
    body.innerHTML = '<p class="text-muted">Загрузка…</p>';
    dialog.showModal();

    try {
      const res = await api.apiFetch('/orders/' + encodeURIComponent(orderId), { headers: api.authHeaders() });
      const order = await res.json();
      const items = (order.items || []).map((item) => `
        <div class="order-detail-item">
          <img src="${esc(item.imagePath || '/img/placeholder.svg')}" alt="" class="order-detail-image">
          <div>
            <div class="order-detail-title">${esc(item.title || 'Товар')}</div>
            <div class="text-muted">Категория: ${esc(item.category || '—')}</div>
            <div>${api.formatPrice(item.price_at_purchase)} × ${Number(item.quantity) || 1}</div>
          </div>
        </div>`).join('');

      body.innerHTML = `
        <h2 id="orderDialogTitle">Заказ #${order.id}</h2>
        <p class="text-muted">${formatDate(order.created_at)} · ${STATUS_LABELS[order.status] || esc(order.status)}</p>
        ${items}
        <p class="order-total" style="margin-top:16px;">Итого: ${api.formatPrice(order.total)}</p>`;

      body.querySelectorAll('img').forEach((img) => {
        img.addEventListener('error', () => { img.src = '/img/placeholder.svg'; }, { once: true });
      });
    } catch (err) {
      body.innerHTML = `<p class="form-error">${esc(err.message)}</p>`;
    }
  }

  async function cancelOrder(orderId, button) {
    if (!confirm('Отменить заказ #' + orderId + '?')) return;
    button.disabled = true;
    try {
      await api.apiFetch('/orders/' + encodeURIComponent(orderId), {
        method: 'PATCH',
        headers: api.authHeaders({ 'Content-Type': 'application/json' }),
        body: JSON.stringify({ status: 'cancelled' })
      });
      loadOrders();
    } catch (err) {
      alert(err.message);
      button.disabled = false;
    }
  }

  // Один обработчик на весь список (кнопки создаются заново при каждой отрисовке)
  container.addEventListener('click', (e) => {
    const button = e.target.closest('button[data-action]');
    if (!button) return;
    const id = button.dataset.orderId;
    if (button.dataset.action === 'details') showDetails(id);
    if (button.dataset.action === 'cancel') cancelOrder(id, button);
  });

  document.getElementById('orderDialogClose').addEventListener('click', () => {
    document.getElementById('orderDialog').close();
  });

  loadOrders();
})();

```js
// ============================================================
// ВОССТАНОВЛЕНИЕ ПАРОЛЯ (forgot.js) — для forgot.html
// Раньше этот код был прямо в HTML внутри <script>...</script>,
// и защита helmet (Content-Security-Policy) его блокировала:
// кнопка «Отправить» ничего не делала.
// ============================================================
(function () {
  'use strict';

  const form = document.getElementById('forgotForm');
  if (!form) return;

  const message = document.getElementById('forgotMessage');
  const button = document.getElementById('forgotBtn');

  function show(text, isError) {
    message.textContent = text;
    message.classList.toggle('form-error', !!isError);
    message.hidden = false;
  }

  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    const email = document.getElementById('femail').value.trim();
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
      show('Введите корректный email', true);
      return;
    }

    button.disabled = true;
    try {
      const res = await window.BuildStoreApi.apiFetch('/auth/forgot', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email })
      });
      const data = await res.json();
      // Сервер специально отвечает одинаково, есть такой email или нет (защита от перебора)
      show((data.message || 'Если email зарегистрирован, вы получите код.') + ' Затем откройте страницу «У меня уже есть код».');
    } catch (err) {
      show(err.message, true);
    } finally {
      button.disabled = false;
    }
  });
})();

// ============================================================
(function () {
  'use strict';

  const form = document.getElementById('resetForm');
  if (!form) return;

  const errorBox = document.getElementById('resetError');
  const button = document.getElementById('resetBtn');

  function showError(text) {
    errorBox.textContent = text;
    errorBox.hidden = false;
  }

  // Одна галочка «Показать пароли» вместо двух кнопок с эмодзи
  document.getElementById('showPasswords').addEventListener('change', (e) => {
    const type = e.target.checked ? 'text' : 'password';
    document.getElementById('newpass').type = type;
    document.getElementById('confirmPassword').type = type;
  });

  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    errorBox.hidden = true;

    const token = document.getElementById('token').value.trim();
    const password = document.getElementById('newpass').value;
    const confirm = document.getElementById('confirmPassword').value;

    if (!/^\d{6}$/.test(token)) return showError('Код — это 6 цифр из письма');
    if (password.length < 6) return showError('Пароль должен содержать минимум 6 символов');
    if (password !== confirm) return showError('Пароли не совпадают');

    button.disabled = true;
    try {
      await window.BuildStoreApi.apiFetch('/auth/reset', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ token, password })
      });
      window.location.href = '/frontend/auth.html';
    } catch (err) {
      showError(err.message); // например «Неверный код или срок действия кода истёк»

С CSP браузер выполняет только файлы с нашего сервера, и такая атака не срабатывает. Это одна из главных защит сайта, поэтому мы подстраиваем код под неё, а не отключаем её.

```js
// ============================================================
// ЛИЧНЫЙ КАБИНЕТ (profile.js) — для dashboard.html
// ============================================================
// Что изменилось по сравнению со старой версией:
// 1. Дата регистрации: сервер присылал число строкой, new Date("179...")
//    давал «Invalid Date». Теперь сервер присылает число (исправлено в db.js),
//    а здесь дополнительно превращаем в Number.
// 2. Баннер статуса организации: «на проверке» / «отклонена» с причиной (ТЗ 5.3).
// 3. Выход удаляет ВСЁ: токен, email и данные пользователя из обоих хранилищ.
// 4. Неверный путь /auth.html исправлен на /frontend/auth.html.
(function () {
  'use strict';

  const api = window.BuildStoreApi;
  const $ = (id) => document.getElementById(id);

  function logout() {
    ['token', 'userEmail', 'user'].forEach((key) => {
      localStorage.removeItem(key);
      sessionStorage.removeItem(key);
    });
    window.location.href = '/index.html';
  }

  function showOrgStatus(me) {
    const box = $('orgStatus');
    if (me.type !== 'organization') return;
    const org = me.organization || {};
    const name = org.org_name ? '«' + org.org_name + '»' : '';
    if (me.status === 'pending') {
      box.className = 'notice notice-warning';
      box.textContent = `Организация ${name} проходит проверку модератором. Размещать объявления можно будет после подтверждения документов.`;
    } else if (me.status === 'rejected') {
      box.className = 'notice notice-danger';
      box.textContent = `Заявка организации ${name} отклонена. Причина: ${me.reject_reason || org.reject_reason || 'не указана'}.`;
    } else if (me.status === 'active') {
      box.className = 'notice notice-success';
      box.textContent = `Организация ${name} подтверждена. В ваших объявлениях отображается пометка «Организация».`;
    } else {
      return;
    }
    box.hidden = false;
  }

  async function loadProfile() {
    if (!api.getToken()) {
      window.location.href = '/frontend/auth.html';
      return;
    }
    try {
      const res = await api.apiFetch('/auth/me', { headers: api.authHeaders() });
      const me = await res.json();

      $('userName').textContent = me.name || 'Пользователь';
      $('userEmail').textContent = me.email;
      $('userType').innerHTML = me.type === 'organization'
        ? '<span class="badge badge-seller-org">Организация</span>'
        : '<span class="badge badge-seller-person">Частное лицо</span>';

      if (me.created_at) {
        const date = new Date(Number(me.created_at));
        $('userSince').textContent = 'На сайте с ' + date.toLocaleDateString('ru-RU', { day: 'numeric', month: 'long', year: 'numeric' });
      }

      document.querySelector('.profile-avatar img').src = me.avatar_path
        ? '/uploads/' + me.avatar_path
        : '/img/default-avatar.svg';

      showOrgStatus(me);
    } catch (err) {
      if (err.status === 401) {
        logout(); // токен просрочен — чистим и отправляем на вход
        return;
      }
      $('userName').textContent = 'Не удалось загрузить профиль';
      $('userEmail').textContent = err.message;
    }
  }

  function uploadAvatar(file) {
    const status = $('avatarStatus');
    if (!file || !file.type.startsWith('image/')) {
      status.textContent = 'Выберите изображение (JPG, PNG или WebP)';
      return;
    }
    if (file.size > 2 * 1024 * 1024) {
      status.textContent = 'Файл больше 2 МБ';
      return;
    }
    status.textContent = 'Загрузка…';
    const reader = new FileReader();
    reader.onload = async () => {
      try {
        const res = await api.apiFetch('/auth/avatar', {
          method: 'POST',
          headers: api.authHeaders({ 'Content-Type': 'application/json' }),
          body: JSON.stringify({ imageBase64: reader.result })
        });
        const data = await res.json();
        document.querySelector('.profile-avatar img').src = data.avatarPath + '?t=' + Date.now();
        status.textContent = 'Аватар обновлён';
      } catch (err) {
        status.textContent = 'Ошибка: ' + err.message;
      }
    };
    reader.readAsDataURL(file);
  }

  $('logoutBtn').addEventListener('click', logout);
  $('avatarInput').addEventListener('change', (e) => uploadAvatar(e.target.files[0]));
  loadProfile();
})();
```

# ЭТАП 9. Git и безопасность

**1. Файл базы не должен лежать в репозитории.** В твоём GitHub есть `backend/users.db`: старая база SQLite с email и хешами паролей. Репозиторий открытый, скачать его может любой. Выполни в корне проекта:

```
git rm --cached backend/users.db
```

`--cached` значит «убери из git, но оставь файл на диске». Если git ответит, что такого файла нет, значит его уже нет в репозитории, и этот шаг пропускай.

**2. Запрети git добавлять такие файлы в будущем.** Открой `.gitignore` в корне и допиши в конец:

```
# Базы данных и загрузки пользователей
*.db
uploads/
server.log
```

> `uploads/` — фото и сертификаты, загруженные на сайт. Это данные пользователей, а не код; в репозитории им не место.

**3. `.env` никогда не коммить.** Он уже в `.gitignore` — проверь командой `git status`, что его нет в списке. Если пароль от базы или `JWT_SECRET` когда-то попадал в git, **смени их**: история git хранит старые версии файлов.

**4. `frontend/js/search.js` больше нигде не подключён** (этап 3.1). Его можно удалить: `git rm frontend/js/search.js`. Если хочешь пока оставить «на память», он ничему не мешает.

**5. Сохрани результат:**

```
git add -A
git status
git commit -m "Исправления: бэкенд, фронтенд, стили"
```

Перед `commit` посмотри вывод `git status`: там не должно быть `.env`, `*.db` и папки `uploads`.

**6. Если всё работает, объедини ветку с основной:**

```
git checkout main
git merge fixes
git push
```
